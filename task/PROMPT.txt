接口验收场景

一个只读跨站收件器通过多条相互独立的链路收到同一份模拟资料的认证分片。任何渠道都可以延迟和重复交付，某一来源也可能签出彼此不一致的分片。编写离线接收和校验程序，输出可以独立复算的资料收齐或隔离回执。模拟以整数向量和可信标记代替真实报文和验签，不打开网络，不需要生成异常网络流量。

输入由已批准的资料清单和分片回执流构成。清单绑定资料 ID、当前代次、源域、收件域、版本截止和内容承诺摘要。分片附链路、来源实例、资料代次、可信标记、生成行向量和载荷符号。约定模 257 的有限域线性关系，测试向量小，各分片可覆盖不同的资料段；跨资料、代次、域或收件窗的分片不能拼用。同一来源实例、代次与分片编号只能绑定一组行及载荷，同号异值将该来源在此代次的所有分片移入待复核集合，重复完全相同的回执只记一次。已越过截止后收到的可信分片留档但不可用于发布。

explain 对每份清单、每个事件前缀验证能否重建并输出一组可复算的来源见证。输入允许最多一个来源域在任一解释下不可靠。分别检查无故障和剔除每个可能不可靠域后，所有余下可信分片对数据向量给出的线性方程是否一致、解是否唯一、且规范编码的承诺摘要是否一致。方程无解的解释不进入结果集合，但仍需保存矛盾证据；至少一个解释有解，且所有有解解释均为唯一解并同清单承诺一致时才可以 release。无解、欠秩、冲突和承诺不符需要不同的证据；对欠秩给一个非零零空间向量，对冲突给所用行 ID 组合及其矛盾等式。见证选择按不同来源域数、分片数和升序 ID 破平；单段足够与全包来源相容需要分别验证。

reuse 使用 SQLite 原子登记资料代次、接收回执与发布回执。并发写入检测出来源异签时必须重核未发布清单；已发布回执按原提交号回读，后续隔离标志独立记录。在回执前后都用进程退出、重启和相同请求重放验证。小规模独立回代应发现满分片但欠秩、错误分片分布在两域、单域孤证无法放行、同 ID 不同代次互不污染、以及协作分片一旦过期不够秩。典型规模 32 行、12 个数据符号、6 个来源域，不允许枚举所有数据向量。

用 Windows 原生 Python 3.12 和纯标准库从空仓库实现，CPU 即可。python -m shard_receipt <命令> CASE.json 读取合成场景，数据库相关命令透过 --db 传路径。结果用确定性 UTF-8 JSON，结构错误易定位。README 给完整格式、规范编码和复跑步骤，同时交付可运行案例及 unittest 断言。
